SpringBoot + MyBatis 实战：从零搭建 RESTful API

2026 年 5 月 · 约 5 分钟阅读

这篇文章记录了我用 SpringBoot + MyBatis 从零搭建 RESTful API 的完整流程，从项目初始化到接口联调，适合刚入门的后端开发者参考。

项目初始化

用 Spring Initializr 生成项目，选三个核心依赖：

Spring Web        → RESTful API 支持
MyBatis Framework → 数据库 ORM
MySQL Driver      → 数据库连接

推荐加上 Lombok 和 Spring Boot DevTools，前者减少样板代码，后者提升开发体验。

项目结构

src/main/java/com/example/demo/
├── controller/   → 接收请求，返回响应
├── service/      → 业务逻辑层
├── mapper/       → 数据库映射接口
├── entity/       → 数据实体类
└── config/       → 配置类（CORS、拦截器等）

这个分层结构是后端项目最常用的模式，清晰、好维护、团队协作友好。

原则：Controller 只负责参数校验和结果返回，Service 做业务逻辑，Mapper 只和数据库打交道。各层各司其职，不要混在一起。

数据库表设计

以一个学员管理系统为例，核心表设计：

CREATE TABLE student (
  id       BIGINT AUTO_INCREMENT PRIMARY KEY,
  name     VARCHAR(50)  NOT NULL,
  class_id BIGINT       NOT NULL,
  phone    VARCHAR(20),
  score    DECIMAL(5,2),
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE class (
  id   BIGINT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL
);

建表时注意几个要点：主键用 BIGINT 自增、时间字段设默认值、外键用逻辑关联（代码层保证）而不是物理外键。

MyBatis 配置与使用

在 application.yml 中配置数据源：

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo
    username: root
    password: your_password
  mybatis:
    mapper-locations: classpath:mapper/*.xml
    type-aliases-package: com.example.demo.entity

Mapper 接口示例：

@Mapper
public interface StudentMapper {
    List<Student> findAll();
    Student findById(Long id);
    int insert(Student student);
    int update(Student student);
    int deleteById(Long id);
}

对应的 XML 文件放在 resources/mapper/ 目录下。

编写 RESTful API

一个完整的 CRUD Controller 长这样：

@RestController
@RequestMapping("/api/students")
public class StudentController {

    @Autowired
    private StudentService studentService;

    @GetMapping
    public Result list() {
        return Result.success(studentService.findAll());
    }

    @GetMapping("/{id}")
    public Result get(@PathVariable Long id) {
        return Result.success(studentService.findById(id));
    }

    @PostMapping
    public Result add(@RequestBody Student student) {
        studentService.insert(student);
        return Result.success(null);
    }

    @PutMapping("/{id}")
    public Result update(@PathVariable Long id,
                         @RequestBody Student student) {
        student.setId(id);
        studentService.update(student);
        return Result.success(null);
    }

    @DeleteMapping("/{id}")
    public Result delete(@PathVariable Long id) {
        studentService.deleteById(id);
        return Result.success(null);
    }
}

统一返回值与异常处理

建议定义一个统一的 Result 类，所有接口返回同样的格式：

public class Result<T> {
    private int code;        // 200 成功
    private String message;  // 提示信息
    private T data;          // 实际数据
    // 省略 getter/setter
    public static <T> Result<T> success(T data) {
        return new Result<>(200, "success", data);
    }
    public static <T> Result<T> error(int code, String msg) {
        return new Result<>(code, msg, null);
    }
}

再用 @ControllerAdvice 统一处理异常，前端拿到的永远是结构一致的 JSON，对接体验好很多。

踩坑提醒：记得配 CORS！前后端分离开发时，浏览器会拦截跨域请求。加一个 CorsConfig 就能解决，两三行代码的事。

总结

这套 SpringBoot + MyBatis + RESTful API 的组合是目前 Java 后端最主流的技术栈之一。从项目初始化到接口联调，整个流程走一遍大概需要 2-3 小时。跑通之后，后面加新接口就是复制粘贴改业务逻辑的事。
