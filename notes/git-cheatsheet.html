常用 Git 命令速查和实用技巧

2025 年 5 月 · 约 4 分钟阅读

Git 是每个开发者的基本功。但大部分人只用 add、commit、push 三板斧。这里整理了一些日常高频命令和救急技巧。

日常三连

git add .
git commit -m "feat: 加了什么功能"
git push

分支操作

# 新建并切换到新分支
git checkout -b feature/xxx

# 切换到已有分支
git checkout main

# 合并分支（当前在 main 时）
git merge feature/xxx

# 删除本地分支
git branch -d feature/xxx

# 删除远程分支
git push origin --delete feature/xxx

撤销与回退

# 工作区的修改全部撤销（还没 add）
git checkout -- 文件名

# 取消暂存（已经 add 了）
git reset HEAD 文件名

# 修改最近一次 commit 的 message
git commit --amend -m "新的提交信息"

# 回退到上一个版本（代码保留）
git reset --soft HEAD~1

# 回退到上一个版本（代码不保留，慎用）
git reset --hard HEAD~1
救急：不小心 reset --hard 弄丢了代码？只要还没 GC，git reflog 可以看到所有操作历史，找到丢失的 commit hash 后用 git cherry-pick 捡回来。

查看历史

# 简洁版日志（一行一个 commit）
git log --oneline

# 图形化分支图
git log --oneline --graph --all

# 查看某文件的历史修改
git log -p 文件名

# 看当前改了哪些文件
git status

贮藏（Stash）

写到一半要切分支？先把当前修改藏起来：

# 暂存当前修改
git stash

# 恢复最近的暂存
git stash pop

# 查看所有暂存列表
git stash list

实用配置

# 设置别名（懒人必备）
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status
# 以后 git st = git status

# 中文文件名不乱码
git config --global core.quotepath false

几条原则

  • 提交信息用英文或中文都行，但要 说清楚做了什么
  • 一个 commit 做一件事，不要混在一起
  • push 前先 pull，有冲突先解决再推送
  • 不要 force push 到共享分支

把这几个记熟，日常开发 90% 的场景都能覆盖了。
