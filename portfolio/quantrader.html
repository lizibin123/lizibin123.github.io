从零搭建的全自动 A 股量化交易系统。覆盖数据获取、因子计算、策略评分、自动交易到风险控制的全链路，无需人工干预。 当前在 openctp 仿真环境稳定运行。

系统架构

  • 双层级评分引擎——Tier 1 选股（基本面+中长期）与 Tier 2 交易（技术面+微观结构）独立评分，避免"好公司没好价格"的问题
  • 20 因子全覆盖——趋势、动量、资金、基本面四大类，基本面权重 1.5 倍
  • 动态股票池——全市场 4000+ → 初筛 → 回测排名 → Top 10，月度调整，月中评分暴跌提前退出
  • 分级建仓——评分 20-40 半仓，40+ 满仓，不搞一把梭

交易执行

  • CTP 协议——C++ shim 封装 + Python ctypes 调用，对接 openctp 仿真交易环境
  • 三个买入窗口——09:25 开盘、12:00 午盘、14:30 尾盘，带限价保护
  • 全时段卖出监控——止损/止盈/移动止损/评分卖出，条件触发立即执行

风控体系（七层）

ATR 止损 1.5× 移动止损 止盈 3.0× 大盘熔断 累计熔断 组合止损 波动率缩仓 跌停处理 连亏冷却

沪深 300 日跌 1.5% 减仓、8% 累计熔断、账户总回撤 12% 全清——每一层都是血泪教训换来的，不是纸上谈兵。

运维与监控

  • 每日自动推送——09:30 / 12:00 / 14:30 / 15:00 四个时段自动生成持仓简报
  • 自动交易集成——跟简报绑定，每次推送检查买卖信号并自动执行
  • 策略健康检查——每周分析因子 IC 衰减、实盘-回测偏差、参数稳定性
  • 滑点敏感性分析——测试不同滑点假设下的策略稳健性

设计原则

仿真是为了找出问题，而不是证明策略有效。 系统经历过数据源中断、CTP 断连、节假日误判、并发写入冲突等线上故障，每一类问题都变成了代码里的一个修复。真正的系统不是在 IDE 里写完就完了，而是在运行中修出来的。

当前运行环境：openctp 仿真交易（≈1000 万模拟资金）· C++ shim + Python · 本地 macOS · 持续运行中
